# OWL reasoning ablation

Generated by `evaluation/prediction/scripts/owl_reasoning_ablation.py`.

The question is what the ontology layer contributes, measured rather than
asserted. Every axiom tested below already existed in
`backend/pipeline/build_ontology.py`; none was added for this analysis.

## Where the reasoner is invoked

| # | site | what it produces |
|---|---|---|
| 1 | `run_reasoner(onto)` after `build_ontology()` | HermiT on the empty schema: checks the class axioms are satisfiable before data is loaded |
| 2 | `populate_and_reason(onto, json)` | 77 Variant individuals carrying five computed features; HermiT then classifies them and the counts are reported before and after |
| 3 | four `.only(ConstrainedDatatype(...))` restrictions on `Variant` | make the ontology inconsistent if an individual asserts a value outside the physical range |
| 4 | Step 4 of `main()` | saves a **schema-only** OWL file; `enrich_graphdb` uploads it to GraphDB as vocabulary |

**No runtime component loads the ontology.** The agents, the ML ensemble
and the Weaviate retrieval path never read it, so nothing the reasoner
concludes can change a prediction. Inferred class memberships are also not
persisted: the saved OWL is rebuilt clean from the schema, so the
classification in site 2 is a build-time report and nothing more.

## What reasoning adds on the current data

All 77 of 77 variants receive an alloy class and a TCP-risk
class. Both are defined by `equivalent_to` axioms over a single numeric
feature -- gamma-prime formers at a 2 wt% cut, Md_avg at the 0.940 / 0.960
/ 0.985 cuts -- so the reasoner is evaluating four threshold comparisons
that the Python feature layer has already computed. It derives no fact
that is not a direct restatement of an input.

| class | count |
|---|---:|
| GammaPrimeAlloy | 64 |
| SolidSolutionAlloy | 13 |
| TCPRiskLow | 34 |
| TCPRiskElevated | 26 |
| TCPRiskModerate | 9 |
| TCPRiskCritical | 8 |

## What reasoning catches: the range axioms

Across the 77 knowledge-graph alloys, **0** violate a range
restriction. The knowledge graph is curated, so a clean result here is
expected and is not evidence the axioms are useless -- it is evidence they
are not currently firing on this input.

Compositions summing outside 98-102 wt%: **5** of 77. No axiom
constrains the composition sum, because the raw composition is never
loaded into the ontology -- only the five derived features are. A
composition that does not add up can only be caught indirectly, if it
pushes one of those five outside its range.

Running HermiT on each of them confirms it. This is the direct answer
to how many records would ingest with a violation undetected:

| alloy | composition sum | HermiT |
|---|---:|---|
| UDIMET* 630 | 103.03% | `consistent` |
| INCONEL* 706 | 102.83% | `consistent` |
| HAYNES* HR-120 | 102.15% | `consistent` |
| IN-102 | 97.09% | `consistent` |
| CM 186LC*(DS) | 97.39% | `consistent` |

All 5 of 5 pass. A composition three percentage
points off closure enters the knowledge graph with nothing raised.

## The PE16 erratum: would an existing axiom have caught it?

NIMONIC PE16 shipped with Ti = 12.0 wt% against a datasheet value of 1.2,
a transposed decimal that also left the composition summing to 110.3%. It
survived ingestion, training and two evaluation campaigns before being
found by hand.

| axiom | range | defective | corrected | violates |
|---|---|---:|---:|---|
| `hasDensityCalculated` | [7.0, 10.0] | 7.384 | 7.936 | no |
| `hasGammaPrimeEstimate` | [0.0, 85.0] | 61.8 | 16.5 | no |
| `hasMdAverage` | [0.7, 1.05] | 1.0599 | 0.9057 | **YES** |
| `hasLatticeMismatchPct` | [-2.0, 2.0] | 1.406 | 0.118 | no |

**Yes.** The defective composition drives `hasMdAverage` to
1.0599, outside its existing range [0.7, 1.05].
The axiom was already in the ontology; had the reasoner been run over
this record at ingestion, the ontology would have been inconsistent and
the defect would have surfaced there rather than six months later.

Two honest qualifications. The margin is thin -- 1.0599 against a bound
of 1.05, so the axiom catches this record by 0.0099 and a smaller
transposition would have passed. And the alloy is an *evaluation*
record: `populate_and_reason` runs over the 77 training alloys only, so
the constraint would not have fired on PE16 in the pipeline as it
stands. Extending ingestion validation to the evaluation set is a
one-line change and is the actionable finding here.

Evaluating the axiom arithmetically shows what should happen. Running

|---|---|
| pe16_corrected | `consistent (classified GammaPrimeAlloy,TCPRiskLow)` |

## Honest positioning

The ontology is **not** currently functioning as data-quality
infrastructure, and the paper should not claim it is. It catches
nothing on the curated 77 alloys because there is nothing there to
catch, and the one real defect the project encountered sat in a record
the validation step never sees.

What the evidence does support is narrower and still worth stating:
the range axioms encode physical bounds that *would* have caught that
defect, which makes them a usable ingestion gate rather than
decoration -- provided ingestion validation is extended to cover every
record entering the system, not just the training set.

Absent that change, the ontology's demonstrated role is **schema and
interoperability**: a shared vocabulary with external alignments,
uploaded to GraphDB, giving the knowledge graph a typed structure and
making it queryable and reusable. That is a legitimate contribution
and it is the one the measurements here support. Claiming the reasoner
improves prediction quality would not be supportable: no runtime
component reads the ontology at all.

## What was deliberately not done

No new axioms were written. It would have been easy to add a
composition-sum restriction, or to tighten the Md bound until PE16 failed
more comfortably, and then report the ontology as having caught a real
error. That would be measuring a constraint built with knowledge of the
answer. The numbers above are what the ontology does as it stands.
